# HA 蓝牙直连移植

## 范围与架构

用户确认仅保留 gateway 接入。采用 `gateway/main@734bbce` 的协议控制器、运行时、配置流程和实体，以 `main@0191d32` 的后续修复为参考进行适配。

数据路径：HA Bluetooth 路由 → Bleak 会话 → MiOT 认证/加密传输 → 运行时状态 → HA 实体。连接、命令和通知共用运行时的命令锁；实体 unique ID 保持 gateway 原有规则。

删除独立服务、MQTT、Web/Docker、巴法云及专用 ESP32 网关。HA 管理的 ESPHome Bluetooth Proxy 仍可作为主动连接路由使用。没有新增充电会话记录或完成事件。

## 行为约定

- 固件协议值位于 PIID 17/18 的高、低半字；第一端口在高半字。协议变化立即重新计算已有端口数据的协议显示。
- 已收到硬件协议时，未知值显示 Unknown；只有尚未取得硬件协议时才使用粗略电压推断。
- GET 错误结果不写入缓存。修改 PIID 16/21 位掩码时，先确保已知当前值，避免默认值误改其它端口。
- 处理常规 Result TLV 和 value 从 offset 12 开始的固件紧凑推送。写入沿用 gateway 的传输 ACK 语义，并用后续推送纠正状态。
- 重连建立全新状态，避免继承上个会话的协议和开关缓存。
- 静默 60 秒后读取固件特征检查链路；静默 180 秒时另做加密 GET 验证会话，允许健康的空闲设备保持连接。
- 认证错误使用分钟级冷却；队列溢出和连续解密失败会触发单设备会话恢复。
- 长期任务使用 HA 后台任务 API，不阻塞 HA 启动；卸载和关机清理连接。

## 验证

`tests/` 使用轻量 HA 模拟对象，但运行真实的 MiOT 数据解析和 AES-CCM 运算。回归覆盖协议推送、设置同步、计数器回绕及坏帧、命令交错推送、位掩码并发写、掉线探测、失败回滚与任务清理。

`tests_ha/` 在独立环境使用真实 Home Assistant 类验证配置流程、实体平台、后台任务与卸载。蓝牙连接本身仍需真实充电器、本机适配器或代理进行验收；这些测试不代表已完成实机验证。

本次本地验证：Python 3.11 / 3.13 各通过 120 项单元测试；Home Assistant 2025.1.4（使用该版本声明的 Bluetooth/USB 依赖）通过 3 项真实 HA 测试，覆盖 47 个实体加载/更新、卸载、关机和配置表单；Ruff、JSON 校验与 Python 打包检查通过。未连接真实充电器，也未执行 GitHub 托管的 HACS/Hassfest 工作流。
